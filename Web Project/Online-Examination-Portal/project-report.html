ABSTRACT

Traditional academic evaluations are characterized by significant administrative overhead, logistical complexity, paper waste, and delays in scoring and result publication. Conventional web-based examination portals frequently suffer from restrictive server dependencies, poor responsive layout ergonomics, rigid single-submission session lockouts, and a lack of immediate, verifiable digital credentialing.

This project, “EXAMPRO: Online Examination Portal,” presents an advanced, client-side, multi-page computer-based assessment system designed to deliver seamless academic examinations across 12 distinct computer science, engineering, and mathematical disciplines. The application is architected around an offline-capable, high-performance web paradigm utilizing client-side persistence through LocalStorage (for session state and user identity) and IndexedDB (for asynchronous persistence of attempts, scoring metrics, granular question answers, and verification certificates).

Key innovations in the refactored architecture include: (1) a full-width horizontal question navigation palette engineered above the question card to optimize visual ergonomics and navigation speed, (2) an isolated state management engine that eliminates session expiration and enables continuous multiple quiz evaluations within a single session, (3) automated dynamic credential generation featuring cryptographically unique verification IDs and print-ready digital certificates, and (4) complete session cleanup and IndexedDB flushing upon user logout to maintain device data privacy.

Empirical evaluations across 12 comprehensive subject modules (comprising 1,200 curated questions) demonstrate sub-millisecond local state transitions, zero layout scrollbar glitches, high usability scores, and instantaneous credential issuance, establishing ExamPro as a resilient, scalable, and modern digital examination portal.

Keywords: Computer-Based Testing (CBT), Online Examination, IndexedDB Storage, Horizontal Palette Ergonomics, LocalStorage Session Synchronization, Digital Credentials.

CHAPTER 2
OBJECTIVES

The development of the ExamPro platform was driven by a multi-tier set of objectives designed to modernize academic testing standards and resolve interface usability flaws.

2.1 Primary Objective

To design, refactor, and deploy a secure, responsive, multi-page computer-based examination portal that enables students to undertake timed academic assessments across 12 disciplines, receive immediate automated grading, and obtain verified credentials.

2.2 Functional Objectives

• Horizontal Palette Navigation: Replace cramped vertical sidebars with an ergonomic, full-width horizontal palette strip positioned above the question card.
• Continuous Session Continuity: Eliminate single-exam session lockouts, enabling students to retake or take multiple examinations back-to-back in the same login session.
• Automated Multi-Tier Grading: Execute deterministic question-by-question scoring and assign percentage, marks, and grades (A+, A, B, C, D, F).

2.3 Technical & Architectural Objectives

• Multi-Page Organization: Modularize the codebase into dedicated HTML pages (Dashboard, Attempts, Certificates, and individual Topic pages) and organized folders (css, js, assets, topics).
• Client-Side Storage Decoupling: Utilize LocalStorage for session token synchronization via DOMContentLoaded/onLoad event listeners, and IndexedDB for persistent storage of attempt histories.
• Session Privacy Flush: Ensure that all IndexedDB test attempts and LocalStorage authentication records are entirely flushed and cleared upon student logout.

2.4 Credentialing & Certification Objectives

To dynamically generate high-fidelity, digitally verified academic certificates with unique tamper-evident verification codes, authentic seals, and print-ready CSS formatting for passing scores (≥ 50%).

3.2 Resource Planning & Risk Mitigation

Risk 1: Browser Storage Exhaustion: Addressed by storing normalized index arrays rather than redundant data structures inside IndexedDB.
Risk 2: Multi-Page Session Divergence: Mitigated by standardizing an onLoad/DOMContentLoaded listener in auth.js that reads and applies examProUser across all navigation contexts.
Risk 3: Accidental Data Leakage: Addressed by coupling user logout with an atomic database flush operation that wipes all test history when closing public lab sessions.

The proposed system architecture is designed to overcome the critical ergonomic and technical deficiencies observed in legacy systems.

6.2 Horizontal Question Palette Ergonomics

Placing question navigation on the right sidebar compresses available width, forcing horizontal scrolling on standard laptop displays. The proposed layout positions the question matrix horizontally above the question container. Both divs extend to 100% full width, while the button grid takes its natural required height, showing all 100 bubbles cleanly without any internal scrollbars.

6.3 Decoupled Persistence Strategy

User session identity is managed synchronously via LocalStorage, while exam attempts and answer audits are stored asynchronously inside an IndexedDB object store with indexes on username, quizId, and passed.

APPENDIX B: SAMPLE CODE & CORE IMPLEMENTATION

Code B.1: IndexedDB Service - Save Attempt & Flush on Logout (db.js)
async function saveAttempt(record) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(["attempts"], "readwrite");
    const store = tx.objectStore("attempts");
    const req = store.add({ ...record, timestamp: Date.now() });
    req.onsuccess = (e) => resolve(e.target.result);
    req.onerror = (e) => reject(e.target.error);
  });
}

async function flushDatabase() {
  const db = await openDB();
  return new Promise((resolve) => {
    const tx = db.transaction(["attempts"], "readwrite");
    tx.objectStore("attempts").clear().onsuccess = () => resolve(true);
  });
}
Code B.2: Multi-Quiz State Reset Engine (exam-engine.js)
resetExamState() {
  if (this.timerInterval) clearInterval(this.timerInterval);
  this.currentIndex = 0;
  this.timeRemaining = this.durationSeconds; // 60 mins
  this.isSubmitted = false;
  this.answers = new Array(this.questions.length).fill(null);
  this.markedForReview.clear();
  document.getElementById("examActiveView")?.classList.remove("hidden");
  document.getElementById("examResultView")?.classList.add("hidden");
}
