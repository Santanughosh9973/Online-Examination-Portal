ABSTRACT

Traditional academic evaluations are characterized by significant administrative overhead, logistical complexity, paper waste, and delays in scoring and result publication. Conventional web-based examination portals frequently suffer from restrictive server dependencies, poor responsive layout ergonomics, rigid single-submission session lockouts, and a lack of immediate, verifiable digital credentialing.

This project, “EXAMPRO: Online Examination Portal,” presents an advanced, client-side, multi-page computer-based assessment system designed to deliver seamless academic examinations across 12 distinct computer science, engineering, and mathematical disciplines. The application is architected around an offline-capable, high-performance web paradigm utilizing client-side persistence through LocalStorage (for session state and user identity) and IndexedDB (for asynchronous persistence of attempts, scoring metrics, granular question answers, and verification certificates).

Key innovations in the refactored architecture include: (1) a full-width horizontal question navigation palette engineered above the question card to optimize visual ergonomics and navigation speed, (2) an isolated state management engine that eliminates session expiration and enables continuous multiple quiz evaluations within a single session, (3) automated dynamic credential generation featuring cryptographically unique verification IDs and print-ready digital certificates, and (4) complete session cleanup and IndexedDB flushing upon user logout to maintain device data privacy.

Empirical evaluations across 12 comprehensive subject modules (comprising 1,200 curated questions) demonstrate sub-millisecond local state transitions, zero layout scrollbar glitches, high usability scores, and instantaneous credential issuance, establishing ExamPro as a resilient, scalable, and modern digital examination portal.

Keywords: Computer-Based Testing (CBT), Online Examination, IndexedDB Storage, Horizontal Palette Ergonomics, LocalStorage Session Synchronization, Digital Credentials.

Built with an offline-resilient, client-side architectural paradigm, ExamPro eliminates network dependency during active tests while delivering instantaneous grading, granular performance analytics, and verifiable digital certificates.

OBJECTIVES

The development of the ExamPro platform was driven by a multi-tier set of objectives designed to modernize academic testing standards and resolve interface usability flaws:

2.1 Primary Objective

To design, refactor, and deploy a secure, responsive, multi-page computer-based examination portal that enables students to undertake timed academic assessments across 12 disciplines, receive immediate automated grading, and obtain verified credentials.

2.2 Functional & Technical Objectives

• Horizontal Palette Navigation: Replace cramped vertical sidebars with an ergonomic, full-width horizontal palette strip positioned directly above the question card.
• Continuous Session Continuity: Eliminate single-exam session lockouts, enabling students to take multiple examinations back-to-back in the same login session without re-authenticating.
• Client-Side Storage Decoupling: Utilize LocalStorage for synchronous session synchronization and IndexedDB for asynchronous attempt histories, with an automated privacy flush upon logout.
• Verified Credential Issuance: Dynamically generate digitally verified academic certificates with unique tamper-evident verification codes and print-ready CSS formatting for passing scores (≥ 50%).

CHAPTER 7
SYSTEM MECHANISM, WORKFLOW & DATA HANDLING
7.1 End-to-End System Workflow (How the Application Works)

The EXAMPRO portal delivers a rapid, dependable examination experience directly inside modern web browsers without requiring complex external backend servers. The workflow operates across eight steps:

Step Workflow Phase Underlying System Operations & Actions
1 Authentication Student enters PIN on login portal. auth.js validates credentials, writes the user identity object to LocalStorage, and redirects to the dashboard.
2 Subject Selection Dashboard dynamically renders 12 discipline cards. Clicking "Start Exam" routes the student to that topic’s interface.
3 Bank Ingestion & Shuffle Topic page loads question dataset, instantiates isolated ExamEngine, normalizes answer keys, and shuffles 100 questions using Fisher-Yates logic.
4 Active Examination Student navigates questions via full-width horizontal numbered palette (1 to 100), selects radio options, or marks items for review.
5 Timer & Auto-Submit 60-minute countdown runs in background. Reaching 00:00 forces auto-submission; student can also submit manually via confirmation modal.
6 Instant Scoring Engine compares recorded selections against correct keys, computes marks/percentage, and assigns letter grades (A+ through F).
7 IndexedDB Persistence Complete attempt payload—marks, question selections, and unique certificate serial ID—is committed asynchronously to IndexedDB.
8 Certification & Review Scores ≥ 50% unlock verifiable digital certificate printable via certificates.html. Historical records are reviewed on attempts.html.

7.2 Core Mechanism & Exam Engine Logic

The examination engine functions as an isolated in-memory state machine. An answers array initialized to null stores user selections (indices 0 to 3), while a JavaScript Set tracks questions flagged as "Marked for Review". The horizontal palette dynamically tracks four distinct visual bubble states: Gray (Unvisited), Blue (Current Question), Green (Answered), and Amber (Marked for Review).

7.2.1 Automated Scoring Algorithm & Grade Computation

Upon exam submission, the ExamEngine.calculateResults() routine evaluates student responses through deterministic client-side logic:

Total Marks = Σ [ (SelectedOption[i] === CorrectAnswerIndex[i]) ? 1 : 0 ]
Percentage = (Total Marks / Total Questions) × 100
Result Status = (Percentage ≥ 50%) ? "PASSED" : "FAILED"

Letter grades are assigned categorically: A+ (90–100%), A (80–89%), B (70–79%), C (60–69%), D (50–59%), and F (<50%). A unique certificate identifier is generated utilizing the format CERT-[TOPIC]-[RANDOM_HASH].

7.3.1 Privacy Protection & Logout Flush Mechanism

When an examinee logs out, the portal invokes ExamDB.flushDatabase() and localStorage.clear(). This wipes all attempt records, answers, and certificates from the browser, ensuring zero residual footprint on shared laboratory computers.

CHAPTER 8
CHALLENGES & PROBLEMS FACED DURING DEVELOPMENT

Developing an offline-capable, client-side examination portal posed several architectural and ergonomics challenges:

8.1 Palette Ergonomics: Sidebar vs. Full-Width Horizontal Layout

Problem: Initial prototypes utilized a vertical right sidebar for 100 question bubbles, causing awkward double scrollbars and squishing question cards.
Solution: Restructured the UI to a 100% full-width horizontal navigation strip placed directly above the question card that wraps dynamically with zero inner scrollbars.

8.2 Multi-Quiz State Contamination & Session Lockouts

Problem: Taking multiple exams consecutively within a single session leaked background timers, retained stale answer arrays, or triggered unwanted lockouts.
Solution: Built an isolated lifecycle reset routine (resetExamState()) inside ExamEngine that clears active intervals and reinitializes arrays while preserving user authentication.

8.3 Cross-Page Identity Desynchronization in Multi-Page Architecture

Problem: Navigating directly between pages (e.g. refreshing attempts.html) led to missing profile headers due to the absence of server session cookies.
Solution: Implemented a synchronous hydration layer in auth.js executing on DOMContentLoaded that reads from LocalStorage and dynamically renders user identity globally.

8.4 IndexedDB Transaction Concurrency & Shared Terminal Privacy

Problem: Asynchronous database writes risked race conditions during fast transitions, and shared college lab terminals presented data leakage risks if attempt histories remained cached.
Solution: Created a promise-based singleton ExamDB wrapper guaranteeing transactional completion, paired with an automated flush routine on logout.

APPENDIX B: SAMPLE CODE & CORE IMPLEMENTATION

Code B.1: IndexedDB Service - Save Attempt & Flush on Logout (db.js)
async function saveAttempt(record) {
  const db = await openDB();
  return new Promise((resolve, reject) => {
    const tx = db.transaction(["attempts"], "readwrite");
    const store = tx.objectStore("attempts");
    const req = store.add({ ...record, timestamp: Date.now() });
    req.onsuccess = (e) => resolve(e.target.result);
    req.onerror = (e) => reject(e.target.error);
  });
}

async function flushDatabase() {
  const db = await openDB();
  return new Promise((resolve) => {
    const tx = db.transaction(["attempts"], "readwrite");
    tx.objectStore("attempts").clear().onsuccess = () => resolve(true);
  });
}

resetExamState() {
